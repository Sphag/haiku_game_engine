# Model Import

The `model` importer (US-020) turns glTF/GLB, FBX, and OBJ sources into the engine's model payload. It runs inside the asset converter, so the runtime never links Assimp (FR-03). Code is in `tools/asset_converter/`: `src/model_importer.cpp` is the Assimp adapter, and `src/model_format.cpp` with `include/asset_converter/model_format.hpp` holds the payload format. Assimp is vendored in `third_party/assimp` and built only by the converter, as a static library with the glTF, FBX, and OBJ importers.

## Using it

A source is registered with a sidecar whose importer is `model`:

```json
"importer": {"type": "model", "settings": {"scale": 1.0}}
```

- `scale` multiplies the whole model. It must be a finite number greater than zero. The default is `1.0`.
- The format is recognized from the bytes, not the file name: `glTF` or a JSON object is glTF/GLB, `Kaydara FBX Binary` or `; FBX` is FBX, and anything else is read as OBJ. A source that is not a model fails with an `IMPORT_FAILED` diagnostic, and no output is written for it.

## Conventions

The engine's frame is Y-up, right-handed, in meters (see `docs/runtime-conventions.md`). The importer produces data in that frame:

- **Axes.** Assimp returns Y-up, right-handed data for all three formats, so no axis change is applied in the adapter. FBX files that declare another up axis are corrected by Assimp's FBX reader from the file's own axis settings; `tests/src/converter_model_tests.cpp` checks a Z-up FBX.
- **Units.** glTF is in meters. OBJ declares no unit, so it is taken as meters. FBX is scaled by its `UnitScaleFactor` (centimeters per unit, `1` by default) divided by 100. Assimp's FBX root transform does not include that factor, so the importer applies it.
- **Transforms.** The conversion (unit factor times `scale`) is applied to the root node. Geometry stays in each node's local space, so the hierarchy is kept as authored. Each node's local transform is stored as a full 4×4 matrix, so non-uniform scale and shear survive.
- **UVs.** `v = 0` is the top row of the texture image, as in glTF. Assimp hands glTF over with `v` already flipped and OBJ and FBX with `v` unflipped, so every format gets `v = 1 - v` here.
- **Tangents.** glTF tangents that the file provides are kept, with the handedness of the file's own bitangent. Every other mesh gets tangents computed from the engine's UVs. These do not use Assimp's tangent-space pass, which works in its own UV space. `bitangent = w * cross(normal, tangent)` follows increasing `v`.
- **Normals.** Normals come from the file. When the file has none, they are generated smoothly.
- **Triangles.** Polygons are triangulated. Point and line faces are skipped and reported.

## Payload

The payload is little-endian binary, named `OWMD`, version 2. Its layout is described at the top of `model_format.hpp`. It holds meshes (positions, and normals, tangents, and UVs when present; bounds; and a LOD chain of indices with meshlets, cooked as described in `mesh-cooking.md`), materials (base color, metallic, roughness, emissive, alpha mode, double-sided flag, and source-relative texture paths), and the node hierarchy with parents before children. `read_model_payload` checks every count against the bytes that remain, and `validate_model` checks indices, material and mesh references, parent order, finite numbers, and UTF-8. The importer validates its output before it writes it, so a payload is valid on both sides.

## Unsupported data

Data the importer does not handle is reported as an `IMPORT_UNSUPPORTED` warning and the rest of the asset is converted. The warnings are stored in the asset's cache manifest, so a cached import reports them again. Current notes cover:

- animations (US-022), skinning data (US-022), and morph targets;
- camera and light objects;
- vertex colors and UV sets after the first;
- point and line faces, triangles that repeat a vertex (dropped by cooking), and meshes that are left with no triangles;
- embedded textures (US-021), which leave the texture reference empty;
- external files that the source names, such as a glTF `.bin` or an OBJ `.mtl`.

External files are not read, because the importer receives only the source bytes. Each refused file is reported once, and the data it would supply falls back to defaults. A glTF that stores its buffer externally fails to import for the same reason, and the failure says so. Materials with missing values get defaults: glTF's defaults for the metallic-roughness block (metallic 1, roughness 1), and metallic 0 with roughness 1 otherwise. Alpha mode comes from glTF's `alphaMode`, or from the opacity for OBJ and FBX. A mask cutoff is taken from glTF only.

## Fixtures

`tests/fixtures/models/` holds one triangle per format, generated by `generate_fixtures.py` (run it with `python3 -I`; the output is checked in):

| Fixture | Checks |
|---|---|
| `triangle_tree.gltf`, `triangle_tree.glb` | Node hierarchy and transforms, UVs, normals, the file's tangent, PBR material, and the vertex-color report. Both files must produce the same payload. |
| `fbx_cm_yup.fbx` | Centimeter units become meters; the model's translation is applied; UVs are flipped; the generated tangent handedness is `-1`. |
| `fbx_m_zup.fbx` | Meter units with a Z-up, right-handed axis setting are converted to Y-up. |
| `triangle.obj` | UVs are flipped; the missing `.mtl` is reported once. |

The tests in `tests/src/converter_model_tests.cpp` also cover the payload format (round trip, malformed bytes, and validation), settings, the `scale` setting, incomplete sources (no normals, UVs, or materials, and line data), and a non-model source. `tests/src/converter_tests.cpp` covers the notes on a cached import and a corrupt model that writes nothing.

## Vendoring note

The vendored Assimp tree needs its root `CMakeLists.txt`, `assimp.pc.in`, and `cmake-modules/` to configure. These are listed in `tools/vendor/vendor.py` and recorded in `third_party/manifest.json` with their hashes. Re-vendor with `python3 -I tools/vendor/vendor.py --download-dir <new empty dir> --only Assimp`.
