# DX12 Device and Presentation

US-027 adds the DirectX 12 backend of the RHI contract (`docs/rhi.md`). It lives in `engine/rhi/src/dx12/` and is built only on Windows. It calls the Windows SDK's `d3d12.h` and `dxgi1_6.h` directly; no DirectX source is vendored.

## What it does

- **Adapter selection.** Adapters are taken in high-performance order. Software adapters (WARP) are skipped. The first hardware adapter that creates a feature level 12_0 device is used. `DeviceDesc::adapter_index` picks one explicitly. Choosing a software adapter that way fails.
- **Debug layer.** `DeviceDesc::debug_layers` enables the D3D12 debug layer with GPU-based validation. `check_debug_messages()` returns every error and corruption message the layer recorded since the last call.
- **Queues and fences.** A graphics, a compute, and a copy queue are created. Each queue has a timeline fence. Every submission signals its queue's timeline, and the object-lifetime rules use those values. A user fence is signaled after the lists execute, and its value must increase.
- **Lifetime.** `destroy` removes the object from its table at once, so the handle is invalid. The object stays alive until every submission that used it completes. It is released once each queue that used it has passed its last use, whether or not the caller waited.
- **Swapchain.** A flip-model swapchain with two or more back buffers, on the graphics queue. Each back buffer remembers the timeline value of the frame that presented it. Acquiring that buffer waits for that value, so frames in flight are bounded by the buffer count.
- **Presentation policy.** `PresentSettings::vsync` sets the sync interval to 1. With vsync off and `allow_tearing` on, the swapchain presents with `DXGI_PRESENT_ALLOW_TEARING` when the adapter reports tearing support. Otherwise vsync stays on. `present_settings()` reports the effective policy.
- **Resize and minimize.** A zero dimension empties the surface: `acquire_back_buffer()` returns nothing and the caller skips the frame. A nonzero size waits for the GPU to go idle, releases the old back buffers, and calls `ResizeBuffers`.
- **Shutdown.** The device waits for every queue before anything is released. A swapchain waits for the GPU and then releases its back buffers in its destructor. Destroy swapchains before their device.
- **Readback.** `copy_texture_to_buffer` writes rows at the 256-byte pitch from `copy_row_pitch`. `read_buffer` reads a `CpuRead` buffer after its fence has completed.
- **Timestamps.** `write_timestamp` resolves into a readback buffer in the same submission. `read_timestamp` returns `NotReady` until that submission completes.
- **Errors.** A device-removed result is returned as `DeviceLost`. Any other failed call is `InvalidState` and names the call and the HRESULT.

## Resources and descriptors (US-029)

- **Buffers.** Each buffer is one committed resource. A `CpuWrite` buffer is upload memory: it is mapped for its whole life, starts in `CopySource`, and `upload_buffer` writes it. A `CpuRead` buffer is readback memory, as before. A constant buffer is padded to 256 bytes, so its view covers whole blocks.
- **Textures.** A depth texture that shaders read is created typeless, so its depth view and its color view can name different formats.
- **Shader-visible heap.** One `CBV_SRV_UAV` heap with 16384 descriptors, shared by every descriptor set. A set takes a contiguous range, first fit, and a released range merges with its neighbours. The GPU reads these descriptors when a submission executes, so a range returns to the heap only when the set is destroyed and no submission that named it is pending. The range is released with the set's last reference, through the same retention as other objects.
- **Views.** A constant buffer binding gets a CBV, a shader-read binding gets an SRV (raw for buffers, 2D for textures), and an unordered-access binding gets a UAV (raw for buffers, 2D for textures, mip 0). A raw buffer view needs a size that is a multiple of four bytes. A texture UAV needs a format D3D12 accepts for typed UAVs: sRGB, BGRA, and depth formats are rejected.
- **Layouts and sets.** A layout records its bindings. A set copies them, so destroying a layout does not affect its sets. Writes check the binding type, the array bounds, and the resource's usage flags.
- **Compute pipelines.** `create_pipeline` builds a root signature with one descriptor table per set. Set `i` is register space `i`, and a binding's register is its binding index. Table ranges follow the layout's binding order, so a set's heap range lines up with its table. Visibility is `ALL`, because a compute pipeline has one stage. The pipeline object is a compute PSO from DXIL.
- **Dispatch.** `set_pipeline` and `set_descriptor_set` bind the root signature, PSO, and the shader-visible heap. `dispatch` checks that every set is bound, every descriptor is written, and every resource is in the state its binding needs. Dispatches are rejected inside a render pass and on the copy queue. Group counts are limited to 65535 per dimension.
- **Queues.** `queue_wait` calls `ID3D12CommandQueue::Wait` on the named queue. The fence value must already be signaled. `upload_buffer` and `read_buffer` both return `NotReady` while a submission that used the buffer is pending.
- **Copies.** `copy_buffer` uses `CopyBufferRegion`. `copy_buffer_to_texture` uses a placed footprint at a 512-byte-aligned offset with 256-byte row pitch, the reverse of `copy_texture_to_buffer`.
- **State mapping.** `ResourceState::ShaderRead` maps to `NON_PIXEL_SHADER_RESOURCE` only. The pixel-shader bit is invalid on a compute queue. Pixel reads need their own state, which no story has added yet. The scene shader (US-033) reads its frame buffer only in the vertex stage, so `NON_PIXEL_SHADER_RESOURCE` is enough.
- **Counts.** `resource_stats()` reports live buffers, textures, and sets, the heap slots those sets hold, and the retained holds. The retained-hold count goes to zero once the submissions that named destroyed objects complete.

## What it leaves to later stories

- **Graphics (US-033).** A graphics pipeline is a vertex and pixel shader pair with fixed state (`docs/rhi.md`). The root signature allows input-assembler input, and each set is a graphics root descriptor table. Vertex and index buffers are bound through `IASetVertexBuffers` and `IASetIndexBuffer` at draw time, so a pipeline change between the two does not matter. Draws call `DrawIndexedInstanced`. `begin_render_pass` sets `RSSetViewports` and `RSSetScissorRects` to the smallest target, and `clear_depth` calls `ClearDepthStencilView`.
- Mesh pipelines (US-038) are a pipeline state stream on `ID3D12Device2`: the optional amplification shader (`AS`), the mesh shader (`MS`), the pixel shader (`PS`), and the same fixed state as a graphics pipeline. `DispatchMesh` runs through `ID3D12GraphicsCommandList6`, and it needs an active pass and a bound mesh pipeline. The feature is `MeshShaderTier` 1 or better, and `DisabledForTest` turns it off. GPU-generated draws (US-037) use `ExecuteIndirect` with one `DrawIndexedInstanced` command signature, made on first use and kept by the device. An indirect count draw passes the count buffer, and DX12 clamps the count to the draw capacity. Per-instance input is input slot 1 with `D3D12_INPUT_CLASSIFICATION_PER_INSTANCE_DATA` and step rate 1.
- The RTV and DSV pools hold 256 and 64 descriptors. They exist only to make the back buffers and render targets work.
- Pixel-shader reads (a `PixelShader`-visible `ShaderRead` state) are not mapped yet.
- `IndirectCount` is reported from hardware support, and indirect-count draws are implemented by US-037. `RayTracing` is covered in the next section.

## Ray tracing (US-041)

`RayTracing` is reported when the adapter's `RaytracingTier` is 1.0 or better and `ID3D12Device5` is available. `DisabledForTest` forces it off, and every ray tracing creation then fails with `FeatureDisabled`. Vulkan reports the same feature from hardware and implements the same contract (US-042, `docs/vulkan.md`).

- **Bottom-level structures** (`create_bottom_level`) hold triangle geometry: float3 positions read from a `Vertex` buffer at a stride and offset, and an optional 16- or 32-bit `Index` buffer. Their input buffers are held by the structure, so their memory outlives it. The buffers need `ShaderResource` usage as well as `Vertex` or `Index`, and a build needs them in `ShaderRead` state, which maps to `NON_PIXEL_SHADER_RESOURCE`. DXR rejects `VertexBuffer` and `IndexBuffer` for this input (the debug layer reports both).
- **Top-level structures** (`create_top_level`) have a fixed instance capacity. `write_top_level` copies the instance list (3x4 transform, instance ID, mask) into upload memory, and the structure keeps the bottom-level structures it names. The write fails with `NotReady` while a submission that uses the structure is pending.
- **Builds and refits.** `build_bottom_level` and `build_top_level` take `BuildMode::Build` or `BuildMode::Refit`. A refit needs `allow_refit` and an earlier build, and a top-level refit keeps the instance count of that build. Deforming geometry is refit in place: the caller rewrites the vertex buffer, then refits. Each structure has one scratch buffer, sized from `GetRaytracingAccelerationStructurePrebuildInfo` for both build and update.
- **Ray pipelines** (`create_ray_tracing_pipeline`) take one DXIL library (`lib_6_3`, built with `DXIL_LIBRARY` in `engine_add_hlsl_shader`) and name its ray generation, miss, and closest-hit entries. The state object is created with a global root signature built the same way as a compute root signature, so set `i` is register space `i`. The three shader identifiers go into a 192-byte upload table once, at creation.
- **Dispatch.** `set_ray_tracing_pipeline` binds the pipeline on the compute root signature, and `set_descriptor_set` binds sets as it does for compute. `dispatch_rays` checks every bound structure: a top-level structure in a set must have been built, and a destroyed one fails the call.
- **Lifetime.** A destroyed structure or pipeline is removed from its table at once. Its memory is kept until every submission that named it completes, as buffers are. A list that names an object destroyed after recording is rejected at submit, and a build that names a destroyed bottom-level structure fails before it is recorded.

Not built here: any-hit and intersection shaders, per-instance hit group selection (every instance uses the one hit group), local root signatures, inline ray queries, compaction, and shared scratch between structures. Vulkan acceleration structures are in `docs/vulkan.md`.

## Running the GPU suite

```text
engine_tests --suite gpu --backend dx12
```

The suite runs only tests tagged `[gpu][dx12]`, and the CPU suites never include them. Each test creates its device with the debug layer on and fails if the layer reports an error. On a host that cannot run the backend, the command exits 3 and prints `unsupported`. WSL and software adapters are not accepted as GPU reports.

`tools/ci/gpu_run.py` wraps the same command for the self-hosted GPU runner and records `passed`, `failed`, or `unsupported` in `artifacts/reports/`.

## Verification record

Verified on 2026-10-22 on Windows with MSVC 14.51 (`win-dev`) on an NVIDIA GeForce RTX 5080:

- `engine_tests --suite gpu --backend dx12`: passed, 8 test cases and 71 assertions, debug layer and GPU-based validation on. The adapter report is printed on stdout with the `[gpu-report]` prefix.
- The smoke test clears an offscreen RGBA8 target and reads the reference color back, then clears and reads back the swapchain back buffer in B8G8R8A8 over three presented frames. It also covers resize, minimize and restore, present-state rejection, fences, and timestamps.

Re-verified on 2026-10-23 with no source change, on the same RTX 5080 and Windows host: `engine_tests --suite gpu --backend dx12` passed with 13 test cases and 508 assertions (the count includes the US-029 resource and descriptor cases). The Vulkan GPU suite on this host passed with 9 test cases and 80 assertions as a cross-check.

Not run: `engine_bench --suite acceptance` (no benchmark harness exists yet, and this story is not on a measured frame path), the editor, and any GitHub CI job (not pushed). The Linux host has no DX12 backend, so the GPU suite there reports `unsupported`.
